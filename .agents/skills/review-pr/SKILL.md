# review-pr

## いつ使うか

PR を開く前、またはローカル変更をコミットする前のセルフレビュー。

## ステップ

1. **差分を取得。** `git diff`（未コミット）または `git diff <base>...HEAD`（ブランチ全体）で変更全体を見る。
2. **セキュリティチェック（最優先）。** `.claude/rules/security.md` に照らす:
   - 秘密情報のハードコード・コミットがないか（`.env`、トークン）。
   - サーバー秘密情報に `NEXT_PUBLIC_` が付いていないか。
   - クライアントコードがサーバー秘密情報を参照していないか。
   - `package.json` / `package-lock.json` / `.npmrc` に不審な依存追加・防御の弱体化がないか。
3. **アーキテクチャチェック。** `.claude/rules/architecture.md` に照らす:
   - EXIF 抽出がサーバー側に漏れていないか。
   - API ルートが `src/app/api/<resource>/route.ts` にあるか。Route Handler 入力にバリデーションがあるか。
   - ポップアップ HTML がエスケープされているか（XSS）。
4. **スタイルチェック。** `npm run check` が通るか。`any` の濫用、列挙値のユニオン型化、Inter 不使用、帰属表示。
5. **メモリ整合性。** 非自明な決定が `memory/decisions.md` に記録されているか。`memory/progress.md` が変更を反映しているか。
6. **報告。** 指摘を「ブロッカー / 推奨 / 任意」で分類して返す。

## 注意

- 違反を見つけても勝手に直さず、まず分類して報告する。セキュリティ違反は即座にユーザーへ surface する。
